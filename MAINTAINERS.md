# Maintainers

## Primary maintainer

- [@Trmachel](https://github.com/Trmachel) — repository owner, architecture, implementation, review, releases, documentation, security triage, and cross-platform compatibility.

## Decision process

The primary maintainer makes final decisions after considering technical quality, user impact, maintenance cost, security, privacy, and license compatibility. Significant behavior changes should be discussed in an issue before implementation.

## Review principles

- Prefer small, reversible changes.
- Require tests for behavior that can be tested automatically.
- Keep media processing local by default.
- Preserve Windows and macOS usability.
- Treat model and dependency licenses as part of product behavior.
- Document known limitations rather than hiding them.

## Adding maintainers

A contributor may be invited as a maintainer after sustained, high-quality participation in reviews, issues, documentation, or releases. Repository access should follow least privilege and may be removed when it is no longer needed.
